## N06 — Default export path assumes backslash separators

`VERIFIED_STATIC` When `excel()` is omitted, the directory of the temporary file is found by searching for a backslash only:

```stata
tempfile xlsxout
local path "`xlsxout'"
local lastslash = strrpos("`path'", "\")
local dirpath = substr("`path'", 1, `lastslash')
local excelout "`dirpath'\\PEA_core_`date'_`time'.xlsx"
```

The same algorithm appears at seven sites: `Stata/plus/_/_pea_export_path.ado:L26-L27`; `Stata/plus/p/pea_core.ado:L46-L51`; `Stata/plus/p/pea_tables.ado:L32-L32`; `Stata/plus/p/pea_figures.ado:L59-L59`; `Stata/plus/p/pea_table11.ado:L50-L50`; `Stata/plus/p/pea_table1_std.ado:L47-L47`; `Stata/plus/p/pea_table_A2_std.ado:L37-L37`.

`INFERRED` On macOS and Linux a `tempfile` path contains only forward slashes, so `strrpos` returns 0, `substr(path, 1, 0)` is empty, and `dirpath` is empty. The literal `\\` in the filename template remains, so the result is a name beginning with a backslash, which is not a path separator on those platforms. The workbook is therefore written outside the intended temporary directory, most likely into the current working directory under an unexpected name, with no error message. On Windows the algorithm works, and the doubled separator is tolerated.

`VERIFIED_STATIC` The logic is duplicated inline at six of the seven sites rather than taken from the helper. `pea_core` does not call `_pea_export_path` at all.

`UNVERIFIED` Also worth a look when this is next touched: in `_pea_export_path.ado` the empty-`excel()` branch returns only `dirpath` through `c_local` at `L27-L27`, while the other branch returns `excelout` at `L35-L35`, so the two branches hand the caller different things. Not investigated further.

This is the finding with the most direct effect on a country team: a Mac user who omits `excel()` cannot find the output and is told nothing. Recorded as a silent failure in `Stata_package/ERRORS.md`. Found 2026-10-16; Stata was not run.
