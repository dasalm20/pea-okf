2. **Transformations applied after ingestion**: any rounding, rescaling, relabelling, year selection or filtering done in R rather than upstream. These are invisible to anyone reading the Stata side and are a likely source of small unexplained differences.
3. **Label-to-field mapping**: what each displayed row is called in the UI versus the underlying field name. The UI label and the source field frequently disagree about the sample, for example an age universe shown as 15+ for a field computed on 15-64.
4. **Which year it selects** when several are available for a country, and whether that matches the Stata package's rule.

Item 3 is the highest priority. A displayed label that misstates the sample will be quoted by readers who never see the code.

## PIP vulnerability precision and PPP concern

`VERIFIED_STATIC` National povvul uses explicit pairs 450−300, 630−420, 1245−840 for 2021 and 322−215, 547−365, 1027−685 for 2017. The poverty-line label lookup maps 2021 umicpl to 8.3; the code’s 840 subtraction differs from that label and from an exact 1.5×8.4 threshold. `data-raw/10-gmi-extended.qmd:L980-L1005`; `R/f-data-prep.R:L52-L67`.

`INFERRED` The import constructs all six pairs after stacking the two PIP files, then splits field suffix PPP into ppp2 and drops ppp2 while retaining the file’s ppp. If both sets of source columns are populated, multiple definitions can be retained under the same displayed PPP/line. Neither actual duplication nor its numerical effect was checked. `data-raw/10-gmi-extended.qmd:L924-L942`; `data-raw/10-gmi-extended.qmd:L980-L1019`. Validate this before treating povvul as a guaranteed exact 1.5×-line band.
