# Record IDs, evidence and graph semantics

Every top-level registry object carries id, record_type, name, source_refs, evidence_status, related_entity_ids, and explanation. Nested source references/transformation fragments are not independent registry entities. Large registries are JSONL. Schemas permit type-specific extension fields.

## IDs

IDs have a type prefix and 16 hexadecimal SHA256 characters. File IDs hash the exact relative path. Blocks hash file path + normalized statement + occurrence ordinal, so inserting unrelated lines does not change an ID. Editing a command, moving a file or inserting an identical statement earlier may change IDs; hashes and source references must then be refreshed. Variables hash file + load/program/frame context + exact symbolic name. These are scoped lexical symbols with an ordered transformation history, not one global variable name. Indicators hash source workflow + resolved field name. Output IDs identify a write site, not just a filename. Dependencies have stable endpoint/relation identities.

## Relationships

- `contains`, `calls`, `invokes_script_candidate`: program/control structure; do not treat contains as numeric influence.
- `reads_candidate`, `expression_dependency`: conservative lexical extraction; INFERRED because macros, options, strings and external schemas can complicate binding.
- `writes`, `produces`, `writes_dataset`, `posts_to_frame`: explicit write sites.
- `potential_dataset_flow`, `possible_output_field`, `contributes_to_output`: bounded candidate reachability, not proof all fields survive filters/reshapes.
- `curated_indicator_input`: reviewed source formula/path link; still inspect the record period scope and upstream boundary.
- `file_data_dependency`, `workflow_prerequisite`: process ordering; not field-level causality.

Direction is source/input → consumer/output. Reverse traversal uses the same edge in reverse. Query tool suppresses inferred edges unless --inferred is selected and follows a dataflow allowlist rather than arbitrary contains/next-block links.

## Symbolic limits

Every `use`/DLW load creates a distinct analysis context. Reloaded datasets do not receive a full SSA/schema reconstruction. Generated instances are expanded only for simple statically enumerated numeric/global loops. `foreach ... of varlist`, wildcard rename, range varlists, helper argument dispatch, runtime returned varlists, frame contents, and full source schemas remain explicit limits. Variable counts therefore count scoped symbols/templates, including lexical candidates, not proven unique runtime columns. Dataset counts include memory/program contexts and symbolic tempfiles; output counts are write sites, including repeated saves and temporary datasets.

Each indicator preserves formula/template, available expansion parameters, sample guards, weighting/aggregation invocation, time scope, outputs and limitations. A formula may be complete while external command internals are absent. No VERIFIED_RUNTIME records were generated.
