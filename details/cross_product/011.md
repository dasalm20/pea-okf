## D17 — Vulnerability: documented PEA differences; GMI definition missing

`VERIFIED_STATIC` PEA Table7 and local C.1 use the interval from the poverty line (inclusive) to line × multiplier (exclusive). Legacy Table1 uses cumulative welfare below 1.5 × line, including poor people. C.1 peers instead subtract two PIP headcounts, rounding the lower cutoff and flooring the upper cutoff, conditional on equality of `onewelfare()` and `pppwelfare()`. These are documented distinct PEA production paths.

PEA evidence on both paths: [Table7](../stata_commands/031.md#s-7b3a6e4e7c4075b8-l1), `Stata/plus/p/pea_table7.ado:L43-L59`; `Stata/plus/p/pea_table7.ado:L115-L206`; [poverty/vulnerability](../stata_commands/039.md#s-8f21c73aab98f587-l1), `Stata/plus/p/pea_table1_std.ado:L154-L158`; [C.1 row 50](../stata_commands/039.md#s-404e09289bf45ca5-l1), `Stata/plus/p/pea_tableC1.ado:L395-L418`.

## D18 — MPM: local helper versus imported cache; GMI production missing

`VERIFIED_STATIC` PEA's local `_pea_mpm` builds deprivation indicators, redistributes weights for unavailable dimensions and thresholds a weighted score at ≥1/3. C.1 imports precomputed peer `mdpoor_i1` through its GMI cache; Figure14/Table6 also use `WLD_GMI_MPM.dta`. A shared field name does not prove identical eligibility, dimension availability or input vintage.

# PEA interaction

**Not a product.** This folder exists for questions that no single product can answer: where two products disagree, what each consumes from the others, and what breaks downstream when one changes.

Status: **PARTIAL_STATIC**, records-only comparison updated 2026-10-15. The [crosswalk](001.md#s-e98fe4c92da718bc-l1) contains 170 shared cell/series templates covering 134 of 284 PEA output records, with 150 rejected records listed individually. Dynamic categories and worksheet aliases are retained as templates; these are not counts of populated workbook cells. Overall correspondences remain `UNVERIFIED`, preserving the weaker source-record qualification.

## Ownership table

Use this when you cannot tell which product a question belongs to.

| Concern | Owner | Notes |
|---|---|---|
| Survey microdata access, harmonised variable names | GMD | `EXTERNAL_DEPENDENCY` to all three products |
| Global comparator indicators (peer countries, regions, income groups) | GMI Extended and external inputs | PEA cache routes are documented; connection to the analysed GMI revision and all dashboard reads remain `UNVERIFIED` |
| PEA table and figure computation from microdata | PEA Stata package | computes the focus-country columns itself |
| Dashboard presentation and calculations | peaApp dashboard | `UNVERIFIED`: implementation and sources are not analysed |
| Poverty lines, PPP vintages | PIP | `EXTERNAL_DEPENDENCY` |

## What belongs in this folder

- [crosswalk.md](001.md#s-e98fe4c92da718bc-l1) — one row per output cell, mapping it across all three products.
- [consumption.md](001.md#s-4c9e6e5e56f9a2b6-l1) — recorded directions, the three C.1 persisted inputs, shared external sources and unresolved delivery bridges.
- [divergences.md](009.md#s-b265441da6fdc5be-l1) — 16 paired mechanisms, including reference period, plus explicit GMI evidence gaps for vulnerability and MPM.
- `change_impact.md` — *(not written)* what to check in the other two products before changing one.

## The core asymmetry, stated once

The built PEA and GMI records document separate definitions and processing paths. No shared definition layer or reconciliation is established by these records. Dashboard behavior remains `UNVERIFIED`. The crosswalk retains each side's samples, fields, reference-period treatment and evidence limits.

Any question of the form "why does A show a different number than B" resolves here first, because both A and B can be internally correct and still disagree.
