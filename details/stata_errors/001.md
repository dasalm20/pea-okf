## N02 — `lstatus()` expects a not-working indicator, not raw `lstatus`

`VERIFIED_STATIC` `pea_tableC1` computes the working-population rows as `_work = \`lstatus' ~= 1`, and its own error message reads "Not working variable must be defined in lstatus()". Under `setting(GMD)`, `pea_core` supplies a variable the package builds itself:

```stata
gen nowork = lstatus==2|lstatus==3 if lstatus~=.
global pea_lstatus "nowork"
label define nowork 0 "Working" 1 "Not working (unemployed or out of labor force)"
```

So `nowork ~= 1` evaluates to working, and the orchestrated path is correct. Evidence: `Stata/plus/_/_pea_vars_set.ado:L58-L66`; `Stata/plus/p/pea_tableC1.ado:L615-L679`.

`INFERRED` A standalone call that passes the raw GMD `lstatus` variable, where 1 = Employed, inverts every row built from `_work`: the share working, poor working, non-poor working, youth working and women working. The two missingness diagnostics in Table C.1.M are conditioned on `_work == 1` and so are computed over the complementary population.

`RUNTIME_CONFIRMED` a given country 0000 GMD, 0000-10-15: passing raw `lstatus` gives [ESTIMATE] for the share-working row against GMI's [ESTIMATE] for the same country-year, consistent with a complement rather than a defect. This is a limited anonymized case, not evidence of general prevalence.

This is a caller contract, not a package defect, and it is easy to hit because the option is named `lstatus()` and the data contains a variable called `lstatus`. Documented as D02 in [PEA_interaction/divergences.md](../cross_product/009.md#s-b265441da6fdc5be-l1). For a standalone call, build the indicator first:

```stata
gen byte nowork = lstatus==2|lstatus==3 if lstatus~=.
```

and pass `lstatus(nowork)`.

`INFERRED` Worth considering as a package change: accept either form and detect which was supplied, or rename the option to reflect what it expects. Neither is proposed here as a defect.

## N03 — `hhid` / `pid` presence check cannot fire

`VERIFIED_STATIC` In the GMD branch of `_pea_vars_set`, the check for `hhid` and `pid` builds a 0/1 indicator and then tests `r(N)`:

```stata
gen ct_`var' = ~missing(`var')
qui su ct_`var', d
if r(N)==0 {
    noi dis as error "Variable `var' has no values/missing in the GMD data. Please check."
    error 1
}
```

Evidence: `Stata/plus/_/_pea_vars_set.ado:L8-L24`.

`INFERRED` `ct_`var'` is 0 or 1 for every observation and is never missing, so after `summarize` the returned `r(N)` equals the number of observations in the data. The guard can therefore fire only on a dataset with zero observations, never on the all-missing `hhid` or `pid` the message describes. The statistic that matches the message is `r(sum)==0` or `r(max)==0`.

`INFERRED` The indicator most likely exists because `hhid` and `pid` can be string, and `summarize` on a string variable returns `r(N)==0`. That is also why the adjacent block at `Stata/plus/_/_pea_vars_set.ado:L26-L36` can summarize its numeric variables directly and still be correct. Two blocks in the same file test the same condition two different ways, and only one of them can fire.

Effect is a silent gate rather than a wrong number: GMD input the check was meant to reject passes through. Severity low to moderate. Found 2026-10-16; Stata was not run.

## N06 — Default export path assumes backslash separators

`VERIFIED_STATIC` When `excel()` is omitted, the directory of the temporary file is found by searching for a backslash only:

```stata
tempfile xlsxout
local path "`xlsxout'"
local lastslash = strrpos("`path'", "\")
local dirpath = substr("`path'", 1, `lastslash')
local excelout "`dirpath'\\PEA_core_`date'_`time'.xlsx"
```

The same algorithm appears at seven sites: `Stata/plus/_/_pea_export_path.ado:L26-L27`; `Stata/plus/p/pea_core.ado:L46-L51`; `Stata/plus/p/pea_tables.ado:L32-L32`; `Stata/plus/p/pea_figures.ado:L59-L59`; `Stata/plus/p/pea_table11.ado:L50-L50`; `Stata/plus/p/pea_table1_std.ado:L47-L47`; `Stata/plus/p/pea_table_A2_std.ado:L37-L37`.

`INFERRED` On macOS and Linux a `tempfile` path contains only forward slashes, so `strrpos` returns 0, `substr(path, 1, 0)` is empty, and `dirpath` is empty. The literal `\\` in the filename template remains, so the result is a name beginning with a backslash, which is not a path separator on those platforms. The workbook is therefore written outside the intended temporary directory, most likely into the current working directory under an unexpected name, with no error message. On Windows the algorithm works, and the doubled separator is tolerated.

`VERIFIED_STATIC` The logic is duplicated inline at six of the seven sites rather than taken from the helper. `pea_core` does not call `_pea_export_path` at all.

`UNVERIFIED` Also worth a look when this is next touched: in `_pea_export_path.ado` the empty-`excel()` branch returns only `dirpath` through `c_local` at `L27-L27`, while the other branch returns `excelout` at `L35-L35`, so the two branches hand the caller different things. Not investigated further.

This is the finding with the most direct effect on a country team: a Mac user who omits `excel()` cannot find the output and is told nothing. Recorded as a silent failure in `Stata_package/ERRORS.md`. Found 2026-10-16; Stata was not run.
